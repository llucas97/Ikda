# 읽다 사진 인증 복약 알람 기획

이 문서는 기획만 담는다. 앱과 서버 코드는 아직 바꾸지 않는다.

자녀가 부모님 약 시간을 맞추고 약봉지(또는 알약) 기준 사진을 찍어 둔다. 부모님도 스스로 맞출 수 있다. 그 시각이 되면 부모님 휴대폰이 울리고, 화면에 `이 약을 찍어주세요`와 기준 사진이 나온다. 지금 찍은 사진이 기준과 비슷하면 알람이 꺼지고 **복용 완료**로 남으며 자녀에게 푸시가 간다. 시간 안에 안 되거나 사진이 계속 안 맞으면 자녀에게 **아직 안 드셨어요**가 간다. 두세 번 안 맞으면 `그냥 먹었어요` 버튼을 보여 주어, 어르신이 알람에 갇히지 않게 한다. 그 경우는 자녀 화면에 따로 표시한다.

지금 코드에 맞춰 적었다. 가족 연결은 `ct_family_link`와 `ct_user_family`, 푸시는 `app/push`의 FCM·가짜 발송, 기한 알림은 `app/lib/services/reminders.dart`의 로컬 알림, 사진 품질은 `server/app/quality.py`와 `app/lib/services/photo_quality.dart`, 서류 보관은 글만 두고 사진은 DB에 넣지 않는 `ct_document` 흐름을 그대로 쓴다.

## 0. 한눈에

| | 첫 버전 (MVP) | 나중 |
|---|---|---|
| 누가 맞추나 | 자녀(연결된 부모님) 또는 부모님 본인 | 같음 |
| 기준 사진 | 알람이 울리는 부모님 폰에만 파일로 둠. 서버 표에는 없음 | 같음 |
| 서버에 남는 것 | 약 이름·시간, 지각 해시, 임베딩 숫자, 복용 기록 | 같음. 사진 파일은 여전히 없음 |
| 같은지 비교 | 기기 안 해시 → 기기 안 임베딩. 서버는 임베딩 숫자만 다시 계산 | 애매한 구간만 Gemini. 사진은 요청 메모리에서만 |
| 알람 | Android 는 정확 알람 + 가능한 만큼 전체 화면. iOS 26+ 는 AlarmKit, 그 아래는 시간 민감 알림 | 폰이 꺼져 있어도 서버가 놓침을 집계 |
| 자녀 알림 | 기존 가족 푸시 (`notify_user`, 잠금 화면에 약 이름 없음) | 같음 |
| 웹 | 알람·카메라 없음 | 자녀가 기록만 보기 |

```
[맞추기] 이름·시각·식전/식후
            │
            ├─ 부모님 폰에서 바로 촬영 ───────────────┐
            └─ 자녀 폰에서 촬영 → 메모리로 잠깐 전달 ─┤  (DB 에 사진 없음)
                                                      ▼
                                            부모님 폰 앱 폴더에 기준 사진
                                            해시·임베딩만 서버에 저장
                                                      │
[약 시간] 로컬 알람이 부모님 폰을 깨움                  │
            ▼                                         │
     "이 약을 찍어주세요" + 기준 사진 ◀────────────────┘
            │  카메라만 (사진첩 없음)
            ▼
     품질 검사(기존 지표) ─ 어두움·흔들림 → 다시 찍기 (실패 횟수 안 셈)
            │ 통과
            ▼
     해시가 매우 가까우면 통과
     아니면 임베딩 코사인
            │
            ├─ 비슷함 → 알람 끔 → 복용 완료 → 자녀 푸시 "약을 드셨어요"
            ├─ 다름 (2~3회) → "그냥 먹었어요" → 따로 기록 → 자녀 푸시
```

서류 기한 알림(하루 전·당일 아침 9시, `inexactAllowWhileIdle`)은 이 기능과 섞지 않는다. 그 알림은 몇 분 늦어도 되고, 복약 알람은 그 시각에 울려야 한다.

## 1. 목표와 쓰는 이야기

### 목표

부모님은 약 시간을 놓치지 않고, 자녀는 "드셨는지"를 전화로 확인하지 않아도 된다. 확인은 **지금 카메라 앞에 그 약이 있는지**까지다. 약을 삼켰는지는 알 수 없다. 의사·약사 지시를 대신하지 않는다. 스토어 문구에도 "복용을 보장한다"고 쓰지 않는다.

### 자녀

1. 연결된 부모님을 고르고, 약 이름(예: 혈압약)과 하루 시각을 넣는다. 병명은 묻지 않는다.
2. 약봉지를 직접 찍거나, 옆에 있으면 부모님 폰으로 찍게 한다.
3. 복용 시각에 푸시로 결과를 본다. 앱을 열면 오늘 약이 `사진으로 확인` / `직접 확인` / `아직` / `놓침` / `늦게 확인` 중 무엇인지 본다. 확인 사진은 자녀 폰에도 서버에도 남지 않는다.
4. 약봉지가 바뀌면 기준 사진만 다시 찍는다. 지난 기록은 그대로다.

### 부모님

1. 자녀가 맞춘 알람을 자기 폰에서 받는다. 자녀가 없으면 스스로 이름·시각·사진을 넣는다.
2. 알람이 울리면 화면의 기준 사진과 같은 약을 찍는다. 맞으면 소리가 멈춘다.
3. 어둡거나 흔들리면 "불을 켜 주세요", "휴대폰을 꼭 잡고 다시 찍어 주세요"처럼 짧은 말로 다시 찍는다. 이 경우는 틀린 것으로 세지 않는다.
4. 두세 번 달라도 `그냥 먹었어요`로 소리를 멈출 수 있다. 자녀에게는 사진 확인과 다르게 간다.

## 2. 지금 구조에 맞추는 원칙

- **사진은 DB에 넣지 않는다.** 서류와 같다. `analysis` 는 요청이 끝나면 메모리에서 비우고, 시험이 SQLite 파일에 사진 바이트가 없는지 본다. 복약도 표에는 글·숫자만 둔다. 기준 사진 파일은 알람이 울리는 부모님 폰의 앱 전용 폴더에만 둔다. 확인용으로 방금 찍은 사진은 비교가 끝나면 메모리에서 버린다. 서류 저장(`shared_preferences`)에도 넣지 않는다. 서류의 `imagePaths` 가 "이번 실행에서만 있고 저장하지 않는다"인 것과 같다.
- **로그인해야 쓴다.** 가족·푸시·기록이 서버에 있다. 서류 분석처럼 비로그인을 허용하지 않는다. `USE_MOCK` 이면 서버 없이 가짜 일정 하나로 화면만 돌고, 푸시는 `NoopPushService` 다.
- **가족 연결이 살아 있고 두 사람 다 활성 회원일 때만** 자녀가 부모님 약을 맞춘다. 역할은 연결마다 정해진다(`docs/phase3-plan.md`). 끊기면 자녀는 더 못 보고(없는 것과 못 보는 것 모두 404), 일정은 부모님 것으로 남는다. 자녀가 보낸 서류가 어르신 것으로 남는 것과 같다.
- **권한은 서류 수정과 따로 둔다.** `can_edit_yn` 은 "대신 서류를 보낼 수 있어요"다. 약 알람까지 묶으면, 서류 권한을 끄자마자 약 알람도 꺼져서 놀란다. `ct_user_family` 에 `can_med_yn` 을 더한다. 기본은 지금 `can_edit_yn` 을 받는 사람(자녀 쪽)과 같게 켜 둔다. 부모님은 자기 약을 항상 맞출 수 있다. 대표가 가족 권한 화면에서 끌 수 있다.
- **푸시는 본 저장이 commit 된 뒤에** `notify_user` 로 보낸다. 실패해도 복용 기록은 남는다. 기기당 8초, 최대 10대, 결과는 `ct_push_log` 한 줄. 문구는 로그에 남기지 않는다.
- **잠금 화면에는 약 이름·병명을 넣지 않는다.** 서류 푸시가 제목·금액을 빼는 것과 같다. 이름은 앱을 열어 로그인한 API 로만 받는다.
- **받는 사람**은 그 부모님과 연결되고, 부모님 줄에서 서류를 볼 수 있으며, `wants_push` 가 켜진 가족이다. 지금 "알림을 받아요" 스위치(`notification_yn`)를 같이 쓴다. 약만 따로 끄기는 나중 질문으로 둔다.
- **화면 말투**는 짧고 글씨는 크다. 먹색 `#1F1D1A`, 종이 `#FFFDF8`, 노랑 `#F2C230` 은 촬영 버튼에만. 버튼 높이 64, 글꼴 IBM Plex Sans KR. 오류 `userMessage` 는 그대로 보여 준다.
- **웹**은 카메라 알람을 하지 않는다. 공유·푸시·스캐너가 없는 것과 같다.
- **다음 마이그레이션은 `V0004` 다.** `V0003__ct_user_family.sql` 까지 있다. AsOne 식 이름을 유지한다. 접두사 `ct_`, PK `<이름>_no`, `_cd`/`_yn`, UTC `TIMESTAMPTZ`, 감사 컬럼, 한국어 COMMENT.

## 3. 화면 흐름

### 들어가는 곳

- **부모님 홈**: `챙길 일` 위에 `약 알람`. 오늘 시각과 한 줄 상태. 없으면 "맞춘 약이 없어요".
- **자녀 홈**: `부모님 서류` 옆에 `약 알람`. 부모님이 두 명 이상이면 "누구 약인가요?"를 먼저 고른다. 연결이 없으면 "가족을 먼저 연결해 주세요"와 가족 화면으로 보낸다.
- 약 목록: 이름, 시각, 오늘 상태. `[약 추가]`, 각 줄에 끄기·사진 바꾸기·지우기.

상태는 다섯이다.

| 화면 말 | 서버 `status_cd` | 뜻 |
|---|---|---|
| 아직 | `PENDING` | 시각이 안 됐거나, 창 안에서 기다리는 중 |
| 사진으로 확인 | `TAKEN` | 사진이 기준과 비슷해 알람을 끔 |
| 직접 확인 | `SELF_REPORTED` | `그냥 먹었어요`. 사진 확인이 아님 |
| 놓침 | `MISSED` | 창이 끝날 때까지 확인이 없음 |
| 늦게 확인 | `LATE` | 놓침 알림 뒤에 같은 날 확인함 |

### 약 추가 (한 번에 하나씩)

1. "무슨 약인가요?" 짧은 이름만. 예: 혈압약. 빈 값이면 "약"이라고 저장하지 않고 다시 묻는다.
2. "언제 드시나요?" 큰 시계. 아침 8시·점심 12시·저녁 7시·자기 전 9시를 제안하고, 직접 고르기도 된다. 하루 최대 8번. 같은 시각 두 번은 막는다.
3. 식전 / 식후 / 상관없음. 선택이다. 알람 화면 작은 글씨로만 보여 준다.
4. 권한을 한 장씩 설명한다. 거절해도 일정은 저장된다. 다만 알람이 약해진다는 말을 큰 글씨로 남긴다. 순서는 §4.
5. "약봉지 찍어 주세요." **이 흐름에는 사진첩 버튼이 없다.** 문서 스캐너(`cunning_document_scanner`)도 쓰지 않는다. 스캐너는 종이 테두리를 자르고, 약봉지·알약에는 맞지 않다. 앱 안의 카메라 미리보기만 쓴다.
6. 기존 품질 검사. 흔들림·빈 사진·너무 작음이면 다시 찍기 화면(지금 `retake_screen` 과 같은 말투). 여기서는 `그래도 보내기`가 없다. 기준 사진이 흐리면 나중에 비교가 계속 실패한다.
7. 미리보기. 사진을 크게 보여주고 `[다시 찍기]` `[이 사진으로]`.
8. 끝 문장: "이 알람은 약 드실 시간을 알려 드리는 거예요. 선생님 말씀을 대신하지 않아요."

자녀 폰에서 찍으면 부모님 폰이 사진을 받아야 알람이 켜진다. 받기 전에는 상태가 "엄마 폰에서 사진을 받으면 알람이 켜져요"이고 알람을 예약하지 않는다. 두 시간 안에 못 받으면 "다시 보내기" 또는 "엄마 폰으로 찍기".

### 알람 화면 (부모님)

- 종이 바탕, 맨 위 큰 글씨 `이 약을 찍어주세요`. 그 아래 기준 사진을 크게. 식전·식후가 있으면 한 줄.
- 노란 촬영 버튼 하나. 사진첩, 공유, 파일 고르기는 없다.
- 손전등 버튼. 기본은 꺼 둔다. 밤에 갑자기 켜지지 않게.
- 맞으면 소리를 멈추고 `잘 드셨어요`를 잠깐 보여 준 뒤 닫는다. 귀 아이콘은 지금 서류처럼 `speech.dart` 로 "이 약을 찍어 주세요"를 읽어 준다.
- 다르면 `이 약과 달라 보여요. 다시 찍어 주세요.` 횟수 숫자는 보여 주지 않는다.
- 품질 때문에 다시 찍을 때는 기존 문구(`photo_dark` 등)를 그대로 쓴다.
- 실패가 기준 횟수(처음 값 3)에 닿으면, 촬영 버튼은 그대로 두고 그 아래 테두리 버튼 `그냥 먹었어요`. 말: "사진이 계속 안 맞아요. 이미 드셨으면 아래를 눌러 주세요."
- 같은 시각에 약이 둘이면 한 화면이 끝난 뒤에 다음 약을 연다. 화면 두 장을 겹치지 않는다.
- 홈 버튼으로 나가도 소리는 창이 끝날 때까지 알림으로 남아 있다. 복용·직접 확인·창 종료만 소리를 끈다. 알림을 지운 것만으로는 복용이 아니다.

### 자녀가 결과를 볼 때

푸시를 누르면 그 약의 오늘 기록으로 간다. 약 이름은 이때 서버에서 받는다. 사진은 없다. `직접 확인`은 "사진 없이 드셨다고 하셨어요"라고 적는다. `사진으로 확인`은 "사진이 기준과 같아서 기록했어요"라고 적는다.

### 약봉지 바꾸기

`약 사진 바꾸기`는 추가 때와 같은 카메라다. 일정 ID 는 유지하고 해시·임베딩만 갈아끼운다. 이미 지난 복용 기록은 바꾸지 않는다. 같은 약이 잇달아 두 번 `직접 확인`이면 목록에 "약봉지가 바뀌었나요? 사진을 다시 찍어 주세요."를 보여 준다.

## 4. 알람

복약 알람은 **부모님 폰의 로컬 알람**이다. 서버 푸시로 깨우지 않는다. 서버 푸시는 자녀에게 결과를 알릴 때만 쓴다. 지금 FCM 은 데이터 알림으로 앱을 정확히 깨우는 용도가 아니고, 앱이 꺼져 있으면 늦거나 빠질 수 있다.

서류 알림 채널 `todo_reminders`(중요도 높음, 정확한 시각 아님)와 가족 채널 `family` 는 그대로 둔다. 복약 전용 채널 `med_alarm` 을 만든다.

권한 안내는 앱을 켤 때가 아니라, **첫 약을 저장할 때** 한 장씩 묻는다. 서류 알림이 첫 예약 때 권한을 묻는 것과 같다.

### Android 13 이상

지금 매니페스트에는 `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`, 카메라, 부팅 뒤 예약 알림 수신기가 있다. 정확한 알람 권한과 전체 화면 권한은 없다. `reminders.dart` 는 `AndroidScheduleMode.inexactAllowWhileIdle` 이라 몇 분 늦을 수 있다고 적혀 있다. 복약만 아래를 쓴다.

**알림 권한 (`POST_NOTIFICATIONS`)**  
Android 13+ 에서 이미 런타임으로 묻는다. 복약도 같은 플러그인 호출을 쓴다. 거절이면 "알림을 허용해 주셔야 약 시간에 울려요"와 설정으로 가는 버튼. 일정은 저장해 둔다.

**정확한 알람**  
`USE_EXACT_ALARM` 은 설치만 하면 허용되지만, Play 정책상 **알람 시계·타이머·달력이 핵심인 앱**만 쓸 수 있다. 읽다의 핵심은 서류 읽기다. 이 권한을 매니페스트에 넣으면 심사가 거절될 수 있다. 쓰지 않는다.

대신 `SCHEDULE_EXACT_ALARM` 을 선언한다.

- Android 12 에서 생겼고, 사용자가 끌 수 있다.
- Android 14 부터는, 타깃이 Android 13 이상인 새로 설치한 앱은 **기본이 거절**이다 (달력·알람 시계로 인정된 경우 제외). 업그레이드로 이미 갖고 있던 허용은 유지된다.
- 예약 전에 `AlarmManager.canScheduleExactAlarms()` 를 본다. 없으면 `Settings.ACTION_REQUEST_SCHEDULE_EXACT_ALARM` 으로 보낸다. 화면에 "약 시간에 맞추어 울리려면 알람 허용이 필요해요"라고 한 줄 적는다.
- 사용자가 바꾸면 `ACTION_SCHEDULE_EXACT_ALARM_PERMISSION_STATE_CHANGED` 를 받아 다시 예약한다.
- 허용되면 `flutter_local_notifications` 의 `AndroidScheduleMode.alarmClock` (`setAlarmClock`) 으로 예약한다. 상태 표시줄에 알람 아이콘이 남아, 어르신이 "알람이 켜져 있다"를 볼 수 있고, 기기가 잠들어도 울릴 이유가 사용자에게 보인다.
- 거절이면 지금 서류 알림과 같은 `inexactAllowWhileIdle` 로 낮추고, "몇 분 늦을 수 있어요"를 약 화면에 남긴다. 앱이 죽지 않게 `SecurityException` 을 삼킨다.

**전체 화면 (`USE_FULL_SCREEN_INTENT`)**  
Android 14+ 에서는 특별 접근이다. **전화·알람이 핵심인 앱만** 설치 때 자동 허용된다. 읽다는 자동 허용을 기대하지 않는다. Play 선언이 필요하면 "자동 허용 대상이 아님, 사용자가 켜면 쓴다"로 적는다.

- 매니페스트에 권한을 넣고, `NotificationManager.canUseFullScreenIntent()` 를 본다.
- 꺼져 있으면 `Settings.ACTION_MANAGE_APP_USE_FULL_SCREEN_INTENT` 로 보낸다. 말: "화면이 꺼져 있어도 약 사진이 나오게 하려면 설정이 필요해요."
- 허용이면 채널 중요도 최대, 범주 `alarm`, 소리 용도 `USAGE_ALARM`, `fullScreenIntent: true`. 열리는 화면은 홈이 아니라 그 회차의 촬영 화면이다. 페이로드는 `med:{doseUid}`. 잠금 위에 보이도록 `showWhenLocked`, `turnScreenOn`.
- 거절이면 머리 위에 뜨는 높은 알림으로 낮춘다. 누르면 같은 촬영 화면. 잠금 화면을 혼자 켜지는 못한다. 이 차이를 설정 화면에 한 줄로 적는다.
- 알림 소리는 한 번만 나므로, 촬영 화면이 열려 있는 동안에는 앱이 `USAGE_ALARM` 으로 짧게 반복한다. 창이 끝나거나 확인되면 멈춘다. 반복이 거슬리면 창(기본 30분) 안에서만 하고, 그 뒤에는 끈다.

**다시 울리기**  
창 기본 30분. 정시, 10분 뒤, 20분 뒤에 같은 회차를 다시 울린다. 새 회차를 만들지 않는다. 창이 끝나면 더 울리지 않는다.

**재부팅·배터리**  
부팅 수신기는 이미 있다. 플러그인으로 예약한 알람은 수신기가 되돌린다. 앱이 다시 켜질 때도 기기 저장 일정으로 한 번 더 맞춘다 (수신기가 놓쳐도 다음 실행에 회복).  
`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 는 Play 에서 막히는 경우가 많아 넣지 않는다. 일부 제조사 폰은 그래도 알람을 재울 수 있다. 그건 나중으로 두고, 설정 앱의 배터리 화면을 여는 안내만 적어 둔다. 강제로 예외를 요구하지 않는다.

**자녀 폰 채널**  
자녀 푸시는 알람 소리가 아니다. 새 채널 `med_family`(중요도 높음, 기본 알림음). 지금 FCM 본문은 채널이 `family` 로 고정이다 (`server/app/push/fcm.py`). `PushMessage` 에 채널을 선택할 수 있게 하고, 비우면 지금처럼 `family` 다. 복약 이벤트만 `med_family`. 앱은 `LocalReminders.init` 옆에서 그 채널을 만든다.

### iOS

**긴급 알림(Critical Alerts)은 일반적으로 쓸 수 없다.** `com.apple.developer.usernotifications.critical-alerts` 권한은 애플이 사례를 심사해 주는 특례다. 약 알림이 이유에 들어갈 수는 있어도, 신청만으로 받을 수 있다고 보면 안 된다. 첫 버전은 이 권한 없이 출시한다. 무음 스위치와 집중 모드를 이 권한으로 뚫을 계획으로 잡지 않는다.

**iOS 26 이상 — AlarmKit (권장)**  
2025년 WWDC 의 AlarmKit 은 시계 앱 알람에 가깝다. 무음 스위치와 집중 모드를 넘어 울리고, 잠금 화면에 시스템 알람이 뜬다. 사람마다 앱 단위로 허용한다.

- `Info.plist` 에 `NSAlarmKitUsageDescription`. 예: "약 드실 시간에 알람을 울리려면 필요해요."
- `AlarmManager.requestAuthorization()`. 거절이면 알람은 예약되지 않는다. 화면에 "알람을 허용하지 않으면 약 시간에 울리지 않아요"라고 분명히 적고, 아래의 시간 민감 알림으로 낮춘다.
- 매일 시각은 `Alarm.Schedule.Relative` (시·분, 매일). 고정 `Date` 는 여행 때 절대 시각이라, "아침 8시"와 어긋날 수 있다.
- 시스템 화면은 우리 Flutter 화면이 아니다. 기준 사진을 그 시스템 화면에 넣을 수 있다고 가정하지 않는다. 버튼 `약 찍기`(App Intent)가 우리 앱의 `이 약을 찍어주세요` 화면을 연다. 사진은 그 화면에 있다.
- `멈추기`는 소리만 끈다. 복용이 아니다. 회차는 `PENDING` 으로 남고, 창이 끝나면 놓침이다.
- 첫 버전은 스누즈를 넣지 않는다. 스누즈를 켜면 창 계산과 시스템 알람이 따로 논다.
- Flutter 공식 패키지가 없으면 얇은 iOS 플러그인으로만 감싼다. 커뮤니티 패키지는 API 가 이 문서와 같은지 확인한 뒤에만 쓴다.

**iOS 18 이하, 그리고 AlarmKit 을 거절한 경우**  
일반 로컬 알림이다.

- 권한은 알림·소리·배지. 지금처럼 첫 약 저장 때 묻는다 (`requestAlertPermission: false` 로 시작해 두고, 필요할 때 요청).
- `interruptionLevel: timeSensitive`. Time Sensitive Notifications capability 가 필요하다. 집중 모드를 항상 뚫지는 못한다. 사용자가 그 집중 모드에서 "시간 민감 알림 허용"을 켜야 한다.
- **옆면 무음 스위치는 그대로 먹힌다.** 긴급 알림이나 AlarmKit 이 아니면 무음을 이길 수 없다. 맞출 때 이 문장을 보여 준다.
- 알림 소리는 최대 30초이고 한 번이다. 창 안에서 10분마다 같은 회차 알림을 다시 예약해 조금 더 알린다. 창이 끝나면 남은 예약을 취소한다.
- 알림을 눌러야 촬영 화면이 열린다. 사용자가 누르기 전에 앱 화면을 강제로 띄우지 않는다. VoIP 푸시(PushKit)로 깨우는 방법은 쓰지 않는다. 통화가 아닌데 쓰면 심사에서 거절된다.

**카메라 문구**  
지금 `NSCameraUsageDescription` 은 서류만 말한다. 약 촬영을 넣으면 "서류와 약을 찍으려면 카메라가 필요해요."처럼 한 문장으로 고친다. 약 흐름은 사진 보관함 권한을 묻지 않는다. `NSPhotoLibraryUsageDescription` 은 서류의 사진첩 고르기에만 남긴다.

**백그라운드**  
iOS 는 앱이 꺼진 동안 우리 화면을 유지하며 소리를 반복할 수 없다. AlarmKit 은 시스템이 울리고, 그 아래 버전은 알림을 누르는 방식이다. 이 차이를 Android 전체 화면과 같은 것처럼 적지 않는다.

## 5. 사진을 비교하는 방법

비교 전에 항상 품질을 본다. 서버·앱이 이미 공유하는 지표다. 긴 변 1000px 흑백, 8×8 칸, 라플라시안 선명도, 평균 밝기, 과노출, 내용 비율. 약 사진은 서류보다 어두워도 비교는 시도한다 (§9). 품질로 다시 찍는 것은 불일치 횟수에 넣지 않는다.

세 가지를 견주어 보고, **기기 안 해시 + 기기 안 임베딩**을 첫 버전으로 고른다. Gemini 는 나중이다.

| | 지각 해시 (dHash) | 기기 안 임베딩 (MobileNet + TFLite) | 서버 Gemini |
|---|---|---|---|
| 하는 일 | 64비트 지문. 해밍 거리가 짧으면 거의 같은 구도 | 224px 로 줄인 사진의 벡터. 코사인 유사도 | 두 장을 보고 같은 약인지 문장으로 판단 |
| 속도 | 아주 빠름 | 중간 폰에서 대략 0.2초 안. isolate 에서 계산 | 서류 분석과 같이 한 건 5~10초 |
| 비용 | 없음 | 앱 크기가 수 MB 늘어남. 호출 비용 없음 | 건당 수 원~십수 원. 애매한 건마다 부르면 금세 늘어남 |
| 빛·각도 | 약함. 약봉지를 조금만 돌려도 거리가 멀어짐 | 빛과 작은 각도 변화에는 해시보다 버팀 | 가장 잘 버팀. 포장 디자인이 완전히 바뀌면 역시 실패 |
| 흰 약병끼리 | 둘 다 밋밋하면 우연히 가깝기도 함 | 서로 다른 약이 가깝게 나올 수 있음. 다른 약과의 간격을 같이 봐야 함 | 이름·색을 말로 묻면 나을 수 있으나 환각이 있다 |
| 개인정보 | 해시만 서버에 둠. 사진 복원은 거의 불가 | 벡터를 서버에 둠. 사진은 아니지만 개인 건강 정보에 가깝게 다룸 | 사진을 서버 메모리로 보냄. 무료 등급 키는 쓰면 안 됨 (`docs/dev-notes.md`) |

**해시로 거절하지 않는다.** 가까우면(가안: 해밍 거리 8 이하) 바로 통과시켜 같은 구도를 다시 찍은 경우를 빨리 끝낸다. 멀다고 바로 "다른 약"이라고 하지 않는다. 각도가 조금만 달라도 64비트 해시는 쉽게 멀어진다. 그 경우는 임베딩으로 넘어간다.

**임베딩**은 MobileNetV3-Small, int8, 분류 층 바로 앞 벡터다 (Small 은 보통 1024차원). ImageNet 평균·분산으로 맞추고, 기준 사진과 확인 사진을 같은 전처리(가운데 정사각, 224)로 돌린다. 모델 파일 이름과 차원을 `embedding_model_cd` 에 적어, 모델을 바꾸면 예전 벡터와 섞지 않는다. 라이선스는 Apache 2.0 인 공식 가중치 계열만 쓴다.

**가안 문턱 (반드시 실제 사진으로 다시 맞춘다).** 서류 품질 문턱이 샘플 다섯 장으로 시작한 것과 같다. 아래 숫자는 측정값이 아니다.

| 결과 | 가안 | 할 일 |
|---|---|---|
| 해시 통과 | dHash 해밍 ≤ 8 | 임베딩 없이 복용 완료. 점수는 해밍 거리를 기록 |
| 임베딩 통과 | 코사인 ≥ 0.86 | 복용 완료 |
| 임베딩 거절 | 코사인 ≤ 0.72 | 불일치 1회. "이 약과 달라 보여요" |
| 그 사이 | 0.72 초과 0.86 미만 | 한 번만 "약에 조금 더 가까이 대고 다시 찍어 주세요." 그래도 그 사이면 불일치 1회 |
| 다른 약과 겹침 | 1등과 2등의 코사인 차이가 0.04 미만 | 통과시키지 않음. "어느 약인지 모르겠어요." |
| 다른 약이 더 가까움 | 예정 약보다 다른 일정의 코사인이 분명히 큼 | "이건 다른 약 같아요." 앱 안에만 그 약 이름을 보여 줌. 잠금 화면 푸시에는 이름을 넣지 않음 |

어르신에게는 **틀린 거절**(분명히 그 약인데 알람이 안 꺼짐)이 더 괴롭다. 그래서 문턱을 끝까지 느슨하게 풀지 않고, `그냥 먹었어요`로 빠져나오게 한다. 느슨한 문턱은 다른 약병을 통과시켜 자녀가 잘못 안심한다. 튜닝 때 틀린 거절과 틀린 통과를 둘 다 센다. 목표의 우선순위는 "같은 약을 세 번 안에 통과"이고, 그 안에 안 되면 직접 확인 버튼이 보여야 한다.

**Gemini 는 첫 버전에 넣지 않는다.** 알람이 울리는 동안 5~10초를 기다리게 하기 어렵고, 약 사진을 무료 등급으로 보내면 안 된다. 나중에는 **애매한 구간만**, 하루 횟수 상한(`MED_GEMINI_DAILY_LIMIT`, 서류 대신 보내기 하루 30회와 같은 종류의 한도), 유료 키, 사진 미저장으로 붙인다. 서류 분석 프롬프트와 합치지 않는다. 그 경로는 서류를 저장하고 금액·할 일을 만든다. 복약은 "같은 약인지"만 예/아니오로 받는 짧은 호출이다. 모델이 죽으면 불일치 1회로 보고 알람 흐름을 막지 않는다.

비교는 기기에서 먼저 끝나 알람을 끈다. 자녀에게 가는 "사진으로 확인"은 서버가 임베딩을 다시 계산해 동의했을 때 보낸다 (§6). 서버 응답을 기다리는 동안 소리를 유지하지 않는다.

## 6. 속이기 어렵게, 그리고 못 막는 것

막으려는 것은 **예전에 찍어 둔 사진을 사진첩에서 다시 내는 것**이다. 주인이 말한 그 경우다.

- 약 흐름은 `image_picker` 의 사진첩·`pickMultiImage` 를 부르지 않는다. 서류의 "사진첩에서 고르기"는 그대로 둔다.
- 시스템 카메라 인텐트도 쓰지 않는다. 제조사 카메라에는 사진첩 썸네일이 달린 경우가 있다. `camera` 패키지로 앱 안에서만 찍는다. Android 는 `ACTION_GET_CONTENT`·`ACTION_PICK` 을 열지 않는다. iOS 는 사진 보관함 선택기를 열지 않는다.
- 바이트는 셔터를 누른 순간에 만들어진다. 파일을 나중에 고를 경로가 없다.
- 서버는 `taken: true` 한 줄만으로 복용 완료를 믿지 않는다. 앱이 새 사진의 임베딩을 보내고, 서버가 저장해 둔 기준 임베딩과 코사인을 같은 문턱으로 계산한다. 통과해야 `TAKEN` 이고 자녀 푸시가 나간다. 점수는 `ct_med_attempt` 에 남기고 사진은 남기지 않는다.
- `그냥 먹었어요`는 서버가 횟수를 확인한다. 불일치가 `MED_FALLBACK_AFTER`(가안 3)보다 적으면 409 `fallback_not_yet`, 말: "사진을 몇 번 더 찍어 주세요." 클라이언트가 버튼을 미리 보여 줘도 서버가 거절한다.
- 창이 지난 뒤의 확인은 `LATE` 다. `TAKEN` 으로 되돌리지 않는다.

**솔직한 한계**

- 약을 삼켰는지는 모른다. 약봉지를 카메라 앞에 두기만 해도 통과할 수 있다.
- 기준 사진을 인쇄해 비추면 통과할 수 있다. 첫 버전에서 "약을 움직여 보세요" 같은 라이브니스는 하지 않는다. 어르신에게 어렵고, 실패가 늘면 알람이 더 답답해진다.
- 앱을 고친 사람은 기준 임베딩을 그대로 다시 보낼 수 있다. 가족 돌봄 기능의 첫 버전 한계로 적고, Play Integrity·App Attest 는 필요가 생긴 뒤에 본다.
- 나중 강화: 확인 사진을 서류 분석처럼 메모리로만 받아 서버가 같은 모델로 임베딩을 직접 계산하고 버린다. 그러면 숫자만 복사하는 방법은 통하지 않는다. 서버에 TFLite 가 필요하다. 시험은 지금처럼 DB 파일에 사진이 없어야 한다.

직접 확인은 속임이 아니라 **다른 기록**이다. 자녀 문구를 복용 완료와 같게 쓰지 않는다.

## 7. 데이터와 API

공통은 지금 API 와 같다. Bearer 필수(아니면 401 `login_required`). `Cache-Control: no-store`. 오류는 `{"error": {"code", "userMessage"}}`. 시각은 UTC `…Z`. 앱과 주고받는 ID 는 `med_…`, `dose_…` (서류의 `doc_` + `secrets.token_hex(10)` 과 같은 방식). 숫자 PK 는 밖으로 내지 않는다. 없는 일정과 권한 없는 일정은 둘 다 404 `med_not_found`.

### 표 (V0004, 아직 만들지 않음)

`ct_user_family.can_med_yn BOOLEAN NOT NULL DEFAULT FALSE` 를 더한다. 이미 있는 연결 중, 주인 줄에서 `can_edit_yn` 이 참인 행만 참으로 채운다. 새 연결을 만들 때(`service` 가 두 줄을 넣는 곳) 서류 수정 권한을 주는 줄에 약 권한도 같이 켠다.

```sql
CREATE TABLE ct_med_schedule (             -- 약 하나. 사진 컬럼 없음
    med_schedule_no BIGSERIAL PRIMARY KEY,
    med_schedule_uid VARCHAR(40) NOT NULL, -- med_…
    owner_user_no BIGINT NOT NULL REFERENCES ct_user(user_no),  -- 약을 드시는 분
    created_by_user_no BIGINT NOT NULL REFERENCES ct_user(user_no),
    family_link_no BIGINT,                 -- 자녀가 만들었으면 그 연결. 본인이면 NULL
    name VARCHAR(40) NOT NULL,             -- 혈압약. 병명 문장 금지
    meal_cd VARCHAR(20) NOT NULL DEFAULT 'ANY',  -- BEFORE / AFTER / ANY
    timezone_cd VARCHAR(64) NOT NULL DEFAULT 'Asia/Seoul',  -- IANA. 시각은 이 지역의 벽시계
    window_min INTEGER NOT NULL DEFAULT 30,

    embedding JSONB,                       -- float 배열. 모델이 없으면 NULL
    embedding_model_cd VARCHAR(40),
    reference_ready_yn BOOLEAN NOT NULL DEFAULT FALSE,  -- 부모님 폰이 사진을 받고 벡터를 올리면 true
    deleted_yn BOOLEAN NOT NULL DEFAULT FALSE,

    created_by BIGINT,

    updated_by BIGINT);
CREATE UNIQUE INDEX ux_ct_med_schedule_uid ON ct_med_schedule (med_schedule_uid);
CREATE INDEX ix_ct_med_schedule_owner ON ct_med_schedule (owner_user_no, updated_at);

CREATE TABLE ct_med_schedule_time (        -- 하루 안의 벽시계 시각. UTC 로 저장하지 않음
    med_time_no BIGSERIAL PRIMARY KEY,
    med_schedule_no BIGINT NOT NULL REFERENCES ct_med_schedule(med_schedule_no),
    time_local CHAR(5) NOT NULL,           -- 08:00
    sort_order INTEGER NOT NULL DEFAULT 0,

CREATE UNIQUE INDEX ux_ct_med_schedule_time ON ct_med_schedule_time (med_schedule_no, time_local);

CREATE TABLE ct_med_dose (                 -- 한 번 드실 차례
    med_dose_no BIGSERIAL PRIMARY KEY,
    med_dose_uid VARCHAR(40) NOT NULL,     -- dose_…
    med_schedule_no BIGINT NOT NULL REFERENCES ct_med_schedule(med_schedule_no),
    owner_user_no BIGINT NOT NULL REFERENCES ct_user(user_no),
    due_at TIMESTAMPTZ NOT NULL,           -- 그 지역 시각을 UTC 로 바꾼 값
    window_end_at TIMESTAMPTZ NOT NULL,
    status_cd VARCHAR(20) NOT NULL DEFAULT 'PENDING',

    match_method_cd VARCHAR(20),           -- PHASH / EMBEDDING / GEMINI / SELF / NONE
    match_score NUMERIC(6, 4),
    mismatch_count INTEGER NOT NULL DEFAULT 0,
    notified_cd VARCHAR(20),               -- NONE / UNCONFIRMED / MISSED / DONE. 같은 종류 푸시는 한 번
    resolved_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),

CREATE UNIQUE INDEX ux_ct_med_dose_uid ON ct_med_dose (med_dose_uid);
CREATE UNIQUE INDEX ux_ct_med_dose_slot ON ct_med_dose (med_schedule_no, due_at);
CREATE INDEX ix_ct_med_dose_owner ON ct_med_dose (owner_user_no, due_at);

CREATE TABLE ct_med_attempt (              -- 찍을 때마다 점수만. 사진·벡터 원문은 넣지 않음
    med_attempt_no BIGSERIAL PRIMARY KEY,
    med_dose_no BIGINT NOT NULL REFERENCES ct_med_dose(med_dose_no),
    method_cd VARCHAR(20) NOT NULL,        -- QUALITY / PHASH / EMBEDDING / GEMINI / SELF

```

활성 일정은 부모님 한 명당 10개(`MED_MAX_SCHEDULES`). 넘으면 409 `med_limit`. 시각은 일정당 8개.

일정 저장 시 서버가 **앞으로 48시간** 회차를 만들어 둔다. 앱도 오프라인을 위해 같은 `dose_` ID 규칙으로 로컬에 만든다. 서버 ID 가 이미 있으면 200으로 기존 것을 돌려주고 덮지 않는다 (서류 `POST /api/documents` 와 같음). 앱은 응답의 `serverTime` 을 다음 `since` 로 쓴다. 폰 시계로 동기화하지 않는다.

`DRAFT` 는 기준 벡터가 아직 없을 때다. 알람을 예약하지 않는다. 벡터가 저장되면 `ACTIVE`.

지우기는 서류처럼 묘비다. 내용(이름, 해시, 임베딩)을 비우고 `deleted_yn`. 다른 기기는 `deleted` 목록으로 로컬 사진·알람을 지운다. 회차도 지운다.

탈퇴(`on_user_withdrawn`)는 내 일정·시각·회차·시도를 지우고, 내가 만들어 준 부모님 일정은 남기되 `family_link_no` 만 끊을 때와 같이 접근만 막는다. 부모님 탈퇴면 그 약 기록 전체가 개인정보로 삭제된다. 임베딩도 삭제다.

연결을 끊으면 자녀 접근만 끊는다. 부모님 폰의 기준 사진과 알람은 유지된다. 자녀 폰에 남아 있던 기준 사진 파일은 앱이 연결 해제 동기화 때 지운다.

### 시각

`time_local` 은 "그 지역에서 아침 8시"다. UTC 로 저장하면 여름시간이 있는 지역에서 하루가 어긋난다. 한국은 여름시간이 없다. 기본 지역은 `Asia/Seoul` 로, 지금 서류 알림이 `Asia/Seoul` 고정인 것과 맞춘다.

회차 `due_at` 은 서버 `zoneinfo` 로 UTC 를 만든다. 그 지역에 여름시간이 있으면, 없는 시각(봄철 공백)은 다음 유효 분으로 미루고, 겹치는 시각(가을)은 첫 번째만 만든다. 시험은 `America/Los_Angeles` 로 이 두 경우를 본다. 제품 기본 지역이 서울이어도 계산 시험은 넣는다.

### 요청

| 요청 | 누가 | 응답 | 오류 |
|---|---|---|---|
| `POST /api/med-schedules` `{name, meal?, times:["08:00"], timezone?}` | 로그인한 본인 (주인) | 201 일정 (`status:"DRAFT"`) | 422 형식, 409 `med_limit` |
| `POST /api/family/links/{linkId}/med-schedules` 같은 본문 | 그 연결의 자녀이고 `can_med_yn` | 201. `owner` 는 부모님 | 404 `link_not_found`, 403 `med_forbidden`, 409 `med_limit` |
| `GET /api/med-schedules?since=` | 내 약, 또는 약 권한이 있는 가족의 약 | `{schedules, deleted, serverTime}` | |
| `PATCH /api/med-schedules/{id}` 이름·시각·식전후·지역·일시정지 | 주인, 또는 `can_med_yn` | 일정 | 404, 403 |
| `DELETE /api/med-schedules/{id}` | 같음 | 204 묘비 | 404, 403 |
| `POST /api/med-schedules/{id}/reference` `{phash, embedding, model}` | **주인 폰만** (사진을 파일로 가진 쪽) | 일정 `ACTIVE` | 422 `embedding_mismatch`(차원·모델), 404 |
| `POST /api/med-schedules/{id}/reference-offer` multipart `image` 1장 | 사진을 찍은 사람 (자녀 또는 주인) | `{offerId, expiresAt}` 메모리에만 보관 | 품질 422 `photo_*`, 413, 415. **DB 에 바이트 없음** |
| `GET /api/med-schedules/{id}/reference-offer/{offerId}` | 주인만 | 이미지 한 번. 그 뒤 메모리에서 삭제 | 404 만료·이미 받음·남의 것 |
| `POST /api/med-doses/{id}/attempts` `{phash?, embedding?, quality?}` | 주인 폰 | `{outcome, mismatchCount, fallback}` | 404, 409 `dose_closed`(이미 끝나 더 못 바꿈) |
| `POST /api/med-doses/{id}/self` | 주인 폰. 불일치가 기준 이상일 때만 | `{status:"SELF_REPORTED"}` | 409 `fallback_not_yet` |
| `POST /api/med-doses/{id}/miss` | 주인 폰이 창 끝에 호출. 이미 끝났으면 빈 성공 | `{status}` | 404 |
| `GET /api/med-doses?since=&scheduleId?` | 주인, 또는 볼 수 있는 가족 | `{doses, serverTime}` | |

`fallback` 이 true 이면 앱이 `그냥 먹었어요`를 보여 준다. 품질 코드가 있으면 `outcome` 은 `RETAKE` 이고 `mismatchCount` 는 그대로다.

기준 사진 전달(`reference-offer`)은 **프로세스 메모리에만** 둔다. 디스크에 쓰지 않는다. 최대 크기는 서류와 같은 `MAX_IMAGE_MB`(기본 10MB). 한 부모님당 대기 3개, 수명 2시간(`MED_OFFER_TTL_MIN`). 받거나 만료되면 바이트를 지운다. 서버가 재시작되면 전달이 사라진다. 그때는 다시 찍는다. 서버가 여러 대면 이 메모리는 그 대에만 있다. 지금 서버는 한 대 가정이다. 여러 대가 되면 설계를 다시 하고, 그때도 표에 사진을 넣지 않는다.

주인 폰이 파일을 저장한 뒤 `reference` 로 벡터를 올려야 `ACTIVE` 다. 자녀가 보낸 벡터를 곧이곧대로 기준 삼지 않는다. 화면에 보이는 파일과 비교 숫자가 부모님 폰에서 나와야 한다.

시도 API 는 임베딩이 있으면 서버가 코사인을 계산한다. 클라이언트가 보낸 `score` 는 무시한다. 해시만 매우 가까우면(≤ 8) 임베딩 없이도 `TAKEN` 이 될 수 있다. 그 경우에도 해시를 서버가 다시 비교한다.

### 푸시

저장이 끝난 뒤에만 보낸다. `data` 에도 약 이름을 넣지 않는다. 앱은 `scheduleId` 로 다시 조회한다. `PushOpen` 은 지금 `type, documentId, linkId` 만 있다. `scheduleId`, `doseId` 를 더한다. `documentId` 에 약 ID 를 넣지 않는다.

| event | 언제 | title / body | data.type |
|---|---|---|---|
| `MED_TAKEN` | 처음 `TAKEN` | 약을 드셨어요 / 약 사진이 맞아 기록됐어요. | `MED_TAKEN` |
| `MED_SELF` | `SELF_REPORTED` | 약을 드셨다고 해요 / 사진 대신 직접 확인했다고 했어요. | `MED_SELF` |
| `MED_UNCONFIRMED` | 불일치가 기준에 닿음. 창이 끝나기 전 | 약을 아직 안 드셨어요 / 사진이 몇 번 맞지 않았어요. | `MED_UNCONFIRMED` |
| `MED_MISSED` | 창 종료이고 아직 한 번도 안 알림 | 약을 아직 안 드셨어요 / 약 드실 시간이 지났어요. | `MED_MISSED` |
| `MED_LATE` | 놓침·미확인 알림 뒤에 같은 날 확인 | 약을 이제 드셨어요 / 늦었지만 확인됐어요. | `MED_LATE` |

한 회차에 `MED_UNCONFIRMED` 와 `MED_MISSED` 를 둘 다 보내지 않는다. 이미 "아직 안 드셨어요"를 보냈으면 창이 끝나도 같은 말을 다시 보내지 않는다. 그 뒤 확인되면 `MED_LATE` 한 번이다. `notified_cd` 로 지킨다.

가족 푸시를 받을 사람이 없으면 `ct_push_log.result_cd = NO_TOKEN` 또는 수신자가 없어 기록만 하고 복용 기록은 남긴다. 본인이 혼자 쓰는 약도 기록은 된다.

### 동기화

서류 `SyncedDocumentRepository` 와 같다. 화면은 기기 저장을 먼저 보여 준다. 로그인 + 서버 모드일 때만 `since` 로 맞춘다. 일시정지·지우기·직접 확인은 기기에 먼저 반영하고 보낼 일 큐에 넣는다. 오프라인이면 알람·비교·직접 확인은 폰에서 되고, 큐가 나중에 서버로 간다. 서버가 거절하면(이미 끝난 회차) 큐에서 빼고 서버 상태를 따른다. 404 도 큐에서 뺀다.

로컬 알람 예약은 서버가 아니라 폰이 한다. 서류를 받아도 기기가 알림을 예약하는 것과 같다. `reference_ready_yn` 이 거짓이거나 로컬에 사진 파일이 없으면 예약하지 않고 "사진을 다시 받아 주세요"를 보여 준다.

## 8. 개인정보

- 기준 사진 JPEG 는 부모님 폰 앱 전용 폴더에만 있다. 갤러리로 복사하지 않는다. 일정 ID 를 파일 이름으로 쓴다. 일정을 지우거나 탈퇴하면 파일도 지운다.
- 자녀 폰은 자기가 방금 찍은 미리보기를 전달이 성공할 때까지만 들고 있다가 지운다. 자녀 화면에 기준 사진을 계속 보여 주지 않는다. 바꾸려면 다시 찍는다.
- 확인 사진은 디스크에 쓰지 않는다. 품질·해시·임베딩 계산이 끝나면 바이트를 버린다.
- 서버 표·로그·푸시 문구·감사 기록에 사진 바이트와 약 이름을 섞지 않는다. `ct_family_log` 에는 `MED_CREATE` 같은 사건과 일정 번호만. `ct_push_log` 는 지금처럼 결과 코드만.
- 임베딩과 해시도 건강에 가까운 값이다. 탈퇴·삭제 때 지우고, 로그에 찍지 않는다. 다른 회원의 벡터와 비교하지 않는다. 비교는 그 일정의 기준 벡터와 그 회차의 새 벡터뿐이다.
- 전달 중 사진은 메모리, 2시간, 한 번 받기. SQLite 파일에 JPEG 매직 바이트(`FF D8 FF`)가 있으면 안 된다. 지금 `test_uploaded_images_are_never_stored` 와 같은 종류의 시험을 복약에도 붙인다.
- Gemini 를 나중에 붙여도 유료 등급 키만 쓴다. 무료 등급은 데이터가 서비스 개선에 쓰일 수 있다고 개발 노트에 적혀 있다. 실제 약 사진에는 그 키를 쓰지 않는다. 환경변수로 꺼져 있으면(`MED_GEMINI=0` 또는 키 없음) 애매한 구간은 불일치로 처리한다.
- 백업: 앱 전용 폴더가 클라우드 백업에 올라가면 기준 사진이 계정 백업에 남을 수 있다. Android 는 그 폴더를 백업에서 빼고, iOS 는 파일에 백업 제외 속성을 둔다.

## 9. 빠지기 쉬운 경우

**약이 여러 개**  
일정은 약마다 따로다. 기준 사진·벡터·시각도 따로다. 한 회차의 임베딩은 그 약과 비교하고, 같은 부모님의 다른 활성 약과도 비교해 §5 간격 규칙을 적용한다. 같은 분에 두 알람이 겹치면 큐로 한 장씩. 먼저 열린 약을 끝내지 않았는데 두 번째 소리가 또 루프를 돌지 않게, 두 번째는 알림만 대기했다가 이어서 연다.

**새 처방전으로 봉지가 바뀜**  
해시·임베딩이 당연히 멀어진다. 불일치를 "안 드심"으로만 보면 자녀가 오해한다. 잇따른 직접 확인 두 번이면 사진 바꾸기를 권한다. 바꾸기 전까지의 `TAKEN` 기록은 옛 기준에 대한 기록으로 남긴다. 이름 자동 채우기(기존 약봉투 분석)는 나중이다. 그 분석을 그대로 호출하면 서류가 하나 저장되므로, 하게 되면 저장하지 않는 짧은 호출로 분리한다.

**어두운 방**  
서류 앱 기준은 평균 밝기 55 미만이면 다시 찍기를 권한다. 머리맡은 그보다 어둡다. 약 촬영만 따로 둔다. 평균 30 미만(가안)은 비교하지 않고 "불이 어두워요. 불을 켜거나 손전등을 눌러 주세요." 실패 횟수에 넣지 않는다. 30 이상 55 미만은 비교는 하되 한 줄만 어둡다고 알려 준다. 손전등은 버튼으로만 켠다. 선명도·빈 사진 기준은 서류 앱과 같은 값을 출발점으로 쓴다.

**놓침과 늦은 복용**  
창(가안 30분) 안에 `TAKEN` 또는 `SELF_REPORTED` 이면 그 상태. 창이 끝날 때까지 아니면 `MISSED` 이고, 아직 안 알렸으면 자녀 푸시 한 번. 그 뒤 같은 지역 달력 날에 확인하면 `LATE` 와 `MED_LATE`. 다음 날 아침 회차가 어제 회차를 완료로 바꾸지 않는다. 어제 것은 `MISSED` 로 남는다. 미래 회차를 미리 찍어서 완료할 수 없다 (`due_at` 이 15분보다 더 미래면 409 `dose_early`, 말: "약 시간이 되면 찍어 주세요."). 15분은 식사 때문에 조금 일찍 드시는 경우를 위한 가안이다.

**오프라인**  
부모님 폰에 일정·사진·벡터가 있으면 알람과 비교는 된다. 자녀 푸시는 온라인이 된 뒤 큐가 서버 확인을 통과하면 나간다. 폰이 꺼져 있어 창 끝 호출을 못 하면, 다음 번 서버 동기화 때 `window_end_at` 이 지났고 `PENDING` 인 회차를 `MISSED` 로 바꾸고 그때 푸시한다. 자녀 알림이 늦어질 수 있다. 첫 버전에는 크론이 없다. 인증 설계에도 크론이 아직 없다. 나중에 Cloud Scheduler 가 내부 주소로 놓친 회차만 훑는다.

**시간대**  
일정은 만든 지역의 벽시계를 유지한다. 휴대폰 지역이 바뀌어도 조용히 옮기지 않는다. "약 알람은 서울 시간 아침 8시로 그대로 둘까요?"를 한 번 묻는다. 서류 알림의 "기기 시간대 따라가기"는 개발 노트의 남은 일이고, 이 기능이 그 일을 대신 끝내지 않는다. 복약만 일정에 지역을 저장한다.

**다시 설치·폰 교체**  
서버에는 벡터와 시각이 있고 사진은 없다. 사진 파일이 없으면 `ACTIVE` 여도 알람을 울리지 않고 "약 사진을 다시 찍어 주세요"를 보여 준다. 옛 벡터는 새 사진이 올라오면 교체한다.

**웹·태블릿**  
웹은 만들기·알람·카메라를 하지 않는다. 열면 "휴대폰 앱에서 약 알람을 맞출 수 있어요." 한 줄이면 된다.

**혼자 쓰는 부모님**  
자녀가 없어도 본인 일정은 된다. 푸시 받을 가족이 없어도 오류가 아니다.

## 10. 단계

### 첫 버전

- 자녀 또는 본인이 이름·시각·식전후를 저장한다. `can_med_yn`.
- 부모님 폰 카메라로 기준 사진. 자녀 폰에서 찍으면 메모리 전달 후 부모님 폰이 벡터를 올린다.
- 카메라만. 품질 실패는 다시 찍기.
- dHash 빠른 통과 + MobileNet 임베딩. 문턱은 가안. Gemini 없음.
- 서버가 임베딩·해시로 `TAKEN` 을 확정. 3회 뒤 `그냥 먹었어요`.
- Android: 알림 권한, `SCHEDULE_EXACT_ALARM`, 가능하면 전체 화면, 아니면 큰 알림. 서류 알림은 정확한 알람으로 바꾸지 않음.
- iOS 26+: AlarmKit. 그 외: 시간 민감 알림. 긴급 알림 권한은 신청하지 않은 채로 출시.
- 회차 기록, 자녀 푸시 다섯 종류, 잠금 화면에 약 이름 없음.
- 약 여러 개의 데이터와 목록. 같은 시각은 한 장씩.
- 사진 바꾸기. 탈퇴·끊기·묘비 동기화.
- `USE_MOCK` 가짜 일정.

### 나중

- 애매한 구간만 Gemini. 유료 키, 하루 한도, 사진 미저장, 서류 분석과 분리.
- 서버가 확인 사진으로 직접 임베딩을 계산하고 버림 (숫자 재전송을 막음).
- 폰이 꺼져 있어도 놓침을 집계하는 예약 작업.
- 약봉투 분석으로 이름만 제안. 서류로는 저장하지 않음.
- 요일 반복, 항생제처럼 끝나는 날.
- 10분 한 번 미루기. AlarmKit 스누즈와 창을 같이 계산할 수 있을 때.
- 약 알림만 따로 끄는 스위치.
- 제조사 배터리 안내. 권한을 강제로 요구하지는 않음.
- 웹에서 자녀가 기록만 보기.

## 12. 테스트

서버는 `cd server && python -m pytest -q`. 앱은 Flutter 가 있는 환경에서 `flutter test`. 개발 노트대로 Flutter 가 없는 PC 에서는 앱 시험을 돌리지 못했다고 구현 보고에 적는다.

**서버**

- 마이그레이션과 모델의 컬럼·유일 색인 이름이 같다 (`test_auth_schema.py` 와 같은 방식).
- 자녀가 만들고 부모님이 벡터를 올리면 `ACTIVE`. 권한 없는 사람·끊긴 연결은 404. 없는 것과 같은 코드.
- `can_med_yn` 이 꺼지면 403 `med_forbidden`. 본인 일정은 된다.
- 기준 사진 전달 뒤 SQLite 파일 전체에 JPEG·PNG 매직 바이트가 없다. 받은 뒤 메모리 보관도 비어 있다. 두 번째 GET 은 404.
- 품질 미달 사진은 422 이고 일정이 생기지 않는다. `photo_blurry` 등 기존 코드.
- 서버가 코사인을 계산한다. 클라이언트가 점수를 100으로 보내도 벡터가 멀면 `MISMATCH`.
- 불일치 3회 전에 `self` 는 409. 3회째에 `SELF_REPORTED` 와 `MED_SELF`. 푸시 제목·본문·data 에 약 이름이 없다.
- 창이 끝나면 `MISSED` 한 번. 이미 `MED_UNCONFIRMED` 를 보냈으면 `MED_MISSED` 를 또 보내지 않는다. 같은 날 뒤늦은 확인은 `LATE`.
- 내일 회차를 오늘 완료할 수 없다.
- 탈퇴하면 임베딩이 포함된 약 행이 없다. 연결 해제 후에도 부모님 조회는 된다. 자녀 조회는 404.
- 서울 08:00 이 맞는 UTC 인지, 로스앤젤레스 전환일(없는 시각·겹치는 시각)에 회차가 하나인지.
- 푸시 발송이 죽어도 회차 저장은 200/201 이다 (`test_push.py` 와 같음).
- 가짜 발송기 시험. FCM 을 실제로 부르지 않는다.

**앱**

- 같은 시험 사진 쌍으로 해시·코사인이 흔들리지 않는다 (같은 입력 ±오차).
- 다른 사진 쌍은 가안 문턱에서 거절된다. 문턱 상수는 한 파일에만 둔다.
- 어두운 사진은 `RETAKE` 이고 불일치 카운트가 오르지 않는다.
- 알람 화면 위젯에 사진첩 버튼이 없다.
- 페이로드 `med:{doseUid}` 가 홈이 아니라 그 회차 화면으로 간다.
- 서류 알림 ID (`notificationIdBase`)와 복약 알림 ID 가 겹치지 않는다.
- `USE_MOCK` 에서 카메라·Firebase 없이 목록이 뜬다.
- 큐: 오프라인 직접 확인이 온라인이 되면 한 번만 전송된다.

**기기에서 볼 것** (자동 시험으로 대신하지 않음)

- Android 13, 14: 알림 권한 거절, 정확한 알람 거절, 전체 화면 거절, 각각 낮춘 동작. 재부팅 뒤 다음 알람이 다시 잡히는지.
- 잠금 화면에서 촬영 화면이 뜨는지(허용했을 때). 홈으로 나가도 창 안에서는 다시 알리는지.
- iOS 26: AlarmKit 허용·거절. 무음 스위치가 켜져 있어도 AlarmKit 은 울리는지. `멈추기`가 복용으로 남지 않는지. 버튼이 촬영 화면을 여는지.
- iOS 18: 시간 민감 알림이 무음 스위치를 못 이기는지(예상된 한계). 알림을 누르면 촬영 화면인지.
- 어두운 방, 손전등, 약 두 개의 같은 시각, 봉지 교체, 창이 지난 뒤의 늦은 확인.
- 자녀 잠금 화면에 약 이름이 안 보이는지.

문턱은 출시 전에 약봉지·알약 쌍 20~30장(같은 약 다른 빛, 다른 각도, 다른 약, 빈 상, 인쇄한 사진)으로 다시 잡는다. `DEBUG` 응답에 점수만 내리고 사진은 남기지 않는다.

## 13. 남은 질문

1. 시간 창은 20분, 30분, 60분 중 무엇으로 둘까. 이 문서는 30분을 가안으로 둔다.
2. `그냥 먹었어요`는 2회 뒤일까 3회 뒤일까. 가안은 3회다. 품질 다시 찍기는 세지 않는다.
3. Play 에 `USE_EXACT_ALARM` 심사를 따로 넣을까. 이 문서는 넣지 않고 `SCHEDULE_EXACT_ALARM` 과 사용자 허용을 권한다. 읽다의 핵심이 알람 시계가 아니기 때문이다.
4. 긴급 알림 특례를 애플에 신청할까. 첫 버전은 신청 없이 AlarmKit 과 시간 민감 알림으로 간다.
5. 지원 iOS 최소 버전. AlarmKit 은 iOS 26 이다. 그 아래를 시간 민감 알림으로 둘지, 약 알람 자체를 26 이상으로 제한할지.
6. 약 푸시를 지금 "알림을 받아요"에 묶을지, 약만 따로 끌지. 첫 버전은 기존 스위치에 묶는다.
7. 자녀가 여러 명이면 모두 받을지. 가안은 보기 권한과 알림이 켜진 연결 모두다.
8. 여행 때 현지 아침 8시로 바꿀지, 집(서울) 8시를 유지할지. 가안은 저장된 지역을 유지하고, 지역이 바뀌면 한 번 묻는다.
9. 기준 사진 전달 2시간이 짧은지. 자녀가 낮에 맞추고 부모님이 저녁에 폰을 켜면 다시 찍어야 한다.
10. 임베딩 모델로 앱이 수 MB 커지는 것을 받아들일지. 해시만으로 가면 오거절이 많아 `그냥 먹었어요`에 자주 기대게 된다.
11. 스토어 문장에서 "약 확인"을 어떻게 말할까. "삼킨 것까지 확인"은 쓰지 않는다.

## 14. 남은 위험

- 첫 버전의 문턱은 측정 전이므로, 실제 약 사진 없이 숫자를 고정하면 알람이 안 꺼지거나 다른 약이 통과한다. 기기 시험 20~30쌍 전에 출시하지 않는다.
- Android 전체 화면과 정확한 알람은 사용자가 거절할 수 있다. 거절 경로를 시험하지 않으면 약이 조용히 안 울린다.
- iOS 18 이하는 무음일 때 시계 알람만큼 못 울린다. 안내 문장을 빼면 자녀가 "앱이 고장"으로 안다.
- 전달 저장소가 메모리라 서버를 재시작하면 기준 사진을 다시 찍어야 한다.
- 제조사 배터리 제한은 이 문서로 해결되지 않는다.
- Flutter 가 없는 환경에서는 앱 알람·카메라 시험을 돌릴 수 없다. 구현은 기기가 있는 곳에서 확인한다.
